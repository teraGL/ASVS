# V5 Обробка файлів

## Мета контролю

Використання файлів може створювати різноманітні ризики для застосунку, зокрема відмову в обслуговуванні (DoS), несанкціонований доступ та вичерпання ресурсів сховища. Цей розділ містить вимоги для усунення цих ризиків.

## V5.1 Документація з обробки файлів

У цьому підрозділі наведена вимога документувати очікувані характеристики файлів, які приймає застосунок, що є необхідною умовою для розробки та перевірки відповідних заходів безпеки.

| # | Опис | Рівень |
| :---: | :--- | :---: |
| **5.1.1** | Перевірити, що документація визначає дозволені типи файлів, очікувані розширення файлів та максимальний розмір (включно з розміром після розпакування) для кожної функції завантаження. Крім того, упевнитися, що в документації описано, яким чином забезпечується безпечність файлів для завантаження та обробки кінцевими користувачами, зокрема як застосунок реагує при виявленні зловмисного файлу. | 2 |

## V5.2 Завантаження файлів і вміст

Функціональність завантаження файлів є основним джерелом надходження недовірених файлів. У цьому підрозділі викладено вимоги, що забезпечують, аби наявність, обсяг або вміст таких файлів не могли завдати шкоди застосунку.

| # | Опис | Рівень |
| :---: | :--- | :---: |
| **5.2.1** | Перевірити, що застосунок приймає лише ті файли, розмір яких він здатен обробити без втрати продуктивності або виникнення атаки типу відмови в обслуговуванні (DoS). | 1 |
| **5.2.2** | Перевірити, що коли застосунок приймає файл — як окремо, так і в складі архіву, наприклад, ZIP-файл — він перевіряє, чи розширення файлу відповідає очікуваному, а також валідовує, що вміст файлу відповідає типу, який визначається цим розширенням. Це включає, але не обмежується перевіркою початкових "magic bytes", перезаписом зображень та використанням спеціалізованих бібліотек для перевірки вмісту файлу. Для рівня L1 ця вимога може застосовуватись лише до файлів, що впливають на ухвалення важливих бізнесових або безпекових рішень. Для рівня L2 і вище, вона має виконуватись для всіх файлів, які приймає застосунок. | 1 |
| **5.2.3** | Перевірити, що застосунок перевіряє стиснені файли (наприклад, zip, gz, docx, odt) на відповідність максимально допустимому розміру після розпакування та максимальній кількості файлів до їх розпакування. | 2 |
| **5.2.4** | Перевірити, що застосовано обмеження на розмір файлів і максимальну кількість файлів на одного користувача, щоб унеможливити заповнення сховища одним користувачем через надмірну кількість файлів або надто великих файлів. | 3 |
| **5.2.5** | Перевірити, що застосунок не дозволяє завантажувати стиснені файли, які містять символічні посилання (symlinks), якщо це не вимагається (у такому випадку необхідно забезпечити наявність дозволеного списку файлів, на які можуть вказувати символічні посилання). | 3 |
| **5.2.6** | Перевірити, що застосунок відхиляє завантажені зображення з розміром пікселів, більшим за максимально дозволений, щоб запобігти pixel flood атакам. | 3 |

## V5.3 Зберігання файлів

У цьому підрозділі наведені вимоги для запобігання неналежному виконанню файлів після завантаження, виявлення небезпечного вмісту та уникнення використання недовірених даних для контролю місця, де зберігаються файли.

| # | Опис | Рівень |
| :---: | :--- | :---: |
| **5.3.1** | Перевірити, що файли, які завантажені або створені з недовірених даних і збережені у публічній директорії, не виконуються як серверний програмний код при безпосередньому доступі через HTTP-запит. | 1 |
| **5.3.2** | Перевірити, що коли застосунок формує шляхи до файлів для операцій з файлами, замість імен файлів, наданих користувачем, він використовує внутрішньо згенеровані або довірені дані. Якщо ж потрібно використовувати імена файлів або метадані, надані користувачем, має застосовуватися сувора валідація та санітизація. Це необхідно для захисту від атак типу path traversal, local or remote file inclusion (LFI, RFI) та server-side request forgery (SSRF). | 1 |
| **5.3.3** | Перевірити, що обробка файлів на стороні сервера, наприклад розпакування файлів, ігнорує інформацію про шлях, надану користувачем, щоб запобігти вразливостям типу zip slip. | 3 |

## V5.4 Завантаження файлів

У цьому підрозділі наведені вимоги для зниження ризиків під час надання файлів для завантаження, зокрема атак типу path traversal та ін’єкційних атак. Також містяться вимоги щодо запобігання наявності в файлах небезпечного вмісту.

| # | Опис | Рівень |
| :---: | :--- | :---: |
| **5.4.1** | Перевірити, що застосунок проводить валідацію або ігнорує імена файлів, надані користувачем, зокрема у JSON, JSONP або URL-параметрах, а також у полі заголовка Content-Disposition у відповіді. | 2 |
| **5.4.2** | Перевірити, що імена файлів, які передаються (наприклад, у заголовках HTTP-відповіді або вкладеннях електронної пошти), кодуються або санітуються (наприклад, відповідно до RFC 6266) для збереження структури документа та запобігання ін’єкційним атакам | 2 |
| **5.4.3** | Перевірити, що файли, отримані з недовірених джерел, скануються антивірусними програмами для запобігання поширенню відомого зловмисного вмісту. | 2 |
